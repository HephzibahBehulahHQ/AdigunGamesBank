# Adigun Game Bank — Pursuing Goals and Template

## Repository

[https://github.com/HephzibahBehulahHQ/AdigunGamesBank](https://github.com/HephzibahBehulahHQ/AdigunGamesBank)

## Mission

Rewrite and redesign every game in this repository to production quality. All games must be real, playable, fully functional games — not dummy, placeholder, or cartoon stand-ins.

## Non‑negotiable quality bar

- Every game must render in **4K / 3D format**.
- Every game must be **fully real and playable** — no placeholders, no fake screens, no "coming soon" buttons.
- Every game must be tested before release.
- Games must be accessible, responsive, and performant.

## Scale target

- **2000 games total**
- Each game must have **10,000 levels**, progressing from **Beginner** to **Professional Master**.
- A level counter does **not** count as a separate game. Each title must be individually designed and tested.

## Must‑have games (priority)

1. **AI Competition Game**
   - All major AI platforms compete: ChatGPT, Claude, Gemini, DeepSeek, Grok, Kimi, Adigun AI, and others.
   - User submits a text or voice prompt.
   - All AIs receive the prompt at the same time, think, and answer.
   - A judge scores each AI on speed, accuracy, quality of suggestions, and other factors that show which AI platform is best.
   - Results must be real live model output — never replay fixtures presented as real output.
2. **Real 4K / 3D Football Game**
   - Full 4K / 3D football experience.
   - Real, playable matches.
   - Licensed or appropriately cleared player, club, and kit content only.
3. **PS5 / PS6 / PS8 Five Games**
   - Five games targeting PS5 / PS6 / PS8.
   - Native console releases require platform‑holder developer access, approved tooling, licensing, and certification.
   - Browser games are not native PlayStation titles. State this honestly until native builds exist.
4. **Electronicer Game**
   - Electrical/electronics engineering game.
   - Real circuits, components, and logic.
   - Fully playable, not a quiz shell.
5. **Religion Game — Bible Story from Genesis to Revelation**
   - The entire Bible story as a playable game, from Genesis to Revelation.
   - Different wars in the Bible from Genesis to Revelation as games, e.g.:
     - Samson War
     - Moses War
     - David War
     - Abimelech
     - and others.
   - The game must cut across all HephzibahBehulahHQ representations.

### Policy rules the designer must obey (from hb-AI-policy)

- Bounded execution — no scope creep beyond the game being built.
- Careful token use — no repeated pasting of unchanged plans or large files.
- Recoverable work — verified checkpoints and backups.
- Meaningful verification — real tests, not self‑declared approval.
- Truthful reporting — never claim a test, build, deployment, or integration occurred without evidence.
- Adopt via the product `AGENTS.md`, recording the exact policy version and immutable commit or release tag.

### Design system rules the designer must obey (from hb-design-system)

- All five divisions inherit the corporate visual foundation.
- A division may apply its approved accent color and specialized components.
- Product application logic stays in its dedicated product repository.
- Shared components must be documented and tested in the consuming product.
- Products adopt design-system changes explicitly; no existing working product is changed by documentation alone.

### Trading standards the designer must obey (from hb-trading)

- Validate financial calculations and data transformations.
- Clearly identify historical, simulated and live data.
- Never represent hypothetical performance as guaranteed returns.
- Protect sensitive financial and personal information.

## Template for every new game

Each game must include:

- **Title**
- **Genre**
- **Target platform(s)**
- **4K / 3D requirement** (confirmed)
- **Level structure**: 10,000 levels, Beginner → Professional Master
- **Controls**: keyboard, touch, and mouse where applicable
- **Accessibility**: keyboard access, contrast, reduced motion, screen‑reader labels
- **Performance**: initial load target, lazy loading of 3D assets
- **Asset rights**: confirmation that all images, audio, and likenesses are licensed or original
- **Testing evidence**: unit, integration, and browser tests
- **Deployment**: GitHub Pages path and verified public URL
- **Status**: Real / In progress / Blocked (with exact dependency)
- **Policy version** adopted (from hb-AI-policy)
- **Design tokens used** (from hb-design-system)

## Realism and honesty rules

- Do not present placeholder content as a finished game.
- Do not claim a game is 4K / 3D unless it actually renders at that quality.
- Do not claim console releases that have not been certified.
- Do not claim live AI output unless a real API is configured.
- Do not use licensed player photos, club crests, kits, or trademarks without rights.
- Do not label a template relabel as a new game.
